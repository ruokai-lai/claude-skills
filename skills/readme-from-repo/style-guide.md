# README Style Guide

## Common Mistakes

- **No install steps** - Never assume setup is obvious
- **No examples** - Show, don't just tell
- **Wall of text** - Use headers, tables, lists
- **Stale content** - Add "last reviewed" date
- **Generic tone** - Write for YOUR audience

## Prose Quality

- **Lead with value** - First 1-2 sentences say what it is and why it exists
- **Be concrete** - Real commands and copy-pasteable examples, not pseudocode
- **Cut filler** - Drop "simply", "just", "easily", marketing adjectives, and boilerplate nobody reads
- **Link, don't duplicate** - Point to deeper docs rather than inlining everything
- **Verify** - Every command and example should match the current project state
- **No invention** - If a fact cannot be verified from the repo, write `TODO: confirm`
